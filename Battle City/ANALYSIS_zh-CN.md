# Battle City 游戏机制分析笔记（中文）

本文档记录从本目录反汇编源码中读出的**游戏机制结论**，供复刻/移植时查阅，避免重复通读 8772 行汇编。

- 分析对象：`bank_FF.asm`（主反汇编，$C000-$FFFF）、`bank_ram.inc`（RAM 映射）、`CHR_ROM.chr`（图形）
- 对照材料：`_misc/Russian disassembly by Griever.asm`、[Habr 逆向文章](https://habr.com/ru/articles/142126/)
- 每条结论都标注了**标签名 + $地址**，可回源码逐条核对
- 版本：Battle City (J)。市面上的 Tank 1990 等盗版改版可能改过逻辑，不适用本文

## 1. 坐标系与地形数据结构

三级粒度，理解这三层是理解一切地形交互的前提：

| 层级 | 尺寸 | 用途 |
|---|---|---|
| block（关卡数据单位） | 16×16 px | 关卡文件里每格 4 bit |
| **tile（运行期地形单位）** | **8×8 px** | 内存中每个 tile 一字节；**坦克通行判定的最小单位** |
| **子块（破坏单位）** | **4×4 px** | 砖 tile 低 4 位的存在掩码 |

- 战场 = 13×13 个 block = 208×208 px
- 每个 block = 2×2 个 tile；运行期地形按 tile 存为一字节 tile ID
- 砖 tile 的**低 4 位是四个 4×4 子块的存在掩码**：`$0F` = 满砖，`$00` = 空
- 子块掩码位序（`sub_D725` @ `$D725`）：`bit=1; if(pos_Y&4) bit<<=2; if(pos_X&4) bit<<=1`
  → **bit0 = 左上，bit1 = 右上，bit2 = 左下，bit3 = 右下**

### tile ID 取值

| 值 | 含义 |
|---|---|
| `$00` | 空 |
| `$01`-`$0F` | 砖（低 4 位为子块掩码） |
| `$10` | 钢墙 |
| `$11` | 战场灰色外框（连 3 星弹都打不掉） |
| `$12` | 水 |
| `$21` | 冰 |
| `$22` | 树（草丛） |
| `$C8`-`$CB` | 老鹰（基地） |
| `>= $80` | 坦克占位的「隐形墙」 |

### 关卡数据格式

- `incbin/stages/stage_01..35.bin`，**每关 91 字节**（13×14 个 block、每 block 4 bit）
- block 类型表 `tbl_DACB` @ `$DACB` 共 16 种，每种展开成 4 个 tile：

  | 值 | 含义 | 展开 |
  |---|---|---|
  | `00` | 右半砖 | `[00,0F,00,0F]` |
  | `01` | 下半砖 | |
  | `02` | 左半砖 | |
  | `03` | 上半砖 | |
  | `04` | 整砖 | `[0F,0F,0F,0F]` |
  | `05`-`08` | 四种半钢 | |
  | `09` | 整钢 | `[10,10,10,10]` |
  | `0A` | 水 | `[12,...]` |
  | `0B` | 树 | `[22,...]` |
  | `0C` | 冰 | `[21,...]` |
  | `0D` / `0F` | 空 | |

- **注意**：原版关卡数据里砖只有「整格 / 上下左右半格」，**没有 1/4 格**。
  基地外壳那圈砖是代码生成的，不在关卡文件里。

## 2. 炮弹与墙体交互

### 2.1 炮弹是一个点

- 出膛位置（`sub_E08C` @ `$E0A2-$E0B6`）：`bullet_pos = tank_pos + 8 * 方向单位向量`
- `tank_pos` 是**坦克中心**；坦克 16×16，实体范围 `[c-8, c+7]`

### 2.2 四个探测点（关键）

`sub_E604_bullets_movement` @ `$E642-$E688`：

设 `u` = **垂直于弹道方向**的坐标（竖直弹取 X，水平弹取 Y），沿弹道方向坐标恒等于子弹位置。
依次探测四点：

```
P1 = u        （总是检测）
P2 = u + 4    （仅当 P1 打掉了砖子块才检测）
P3 = u - 1    （总是检测）
P4 = u - 5    （仅当 P3 打掉了砖子块才检测）
```

- 方向分量取自 `tbl_EA49`(dX) = `[00,FF,00,01]`、`tbl_EA4D`(dY) = `[FF,00,01,00]`（0=上,1=左,2=下,3=右）
- 偏移量 = 4 × |垂直单位向量|，**所以偏移永远垂直于弹道**
- 覆盖像素区间 `[u-8, u+7]` = **16px，恰好等于坦克宽度**

### 2.3 单点命中判定

`sub_E69A` @ `$E69A`：

1. 取 `tile = field[y>>3][x>>3]`、`bit` = 4×4 掩码位
2. `(tile & (0xF0|bit)) == 0` → 此处为空，子弹继续飞
3. `(tile & 0xFC) == 0xC8` → 老鹰，游戏结束
4. `tile >= 0x12`（水/冰/树）→ **子弹穿过，不停**
5. 否则子弹在此爆炸（`status=$33`），并且：
   - `tile == 0x11`（外框）→ 什么都不掉
   - **3 星强弹**（`bullet_property & 0x02`）→ **整个 8×8 tile 直接写 0**（砖、钢通吃），返回 0（不触发外扩探测）
   - `tile == 0x10`（钢墙）普通弹 → 不掉
   - 砖（`$01`-`$0F`）→ `tile &= ~bit`，**只清掉命中的那 1 个 4×4 子块**（`sub_D743` @ `$D743`），返回 1（允许向外再探一格）

### 2.4 净效果

| 弹种 | 一发清除范围 | 打穿一整瓦（16px 厚）所需 |
|---|---|---|
| 普通弹 / 1-2 星 | **16 宽 × 4 深** | **4 发** |
| 3 星强弹 | **16 宽 × 8 深**，可破钢 | 2 发 |

- 慢弹 2px/帧但隔帧处理、快弹 4px/帧每帧处理 → 等价于**都是每前进 4px 检查一次**，故「一发只吃 4px 深」在两种弹速下都成立
- **子弹自身的通过判定只用 `u-1` 和 `u` 两点**，所以 8px 宽的通道子弹能过、16px 的坦克过不去（原版常见的「子弹能过、坦克过不去」窄缝）

### 2.5 残砖现象的成因

若内侧格（`u` 或 `u-1`）已经是空的，**外侧格根本不会被检测**，于是打不掉。
这就是坊间说的「砖墙打几发后剩下打不掉的残砖、仍然挡路」。

### 2.6 子弹属性

`sub_E08C` @ `$E0BC-$E0D5`，按 `tank_type & 0xF0` 设置 `bullet_property`：

| 坦克 | property | 含义 |
|---|---|---|
| 玩家 3 星（`$60`） | `$03` | 快弹 + **强弹**（整 tile 清零、可破钢） |
| 玩家 1-2 星（`$20`/`$40`） | `$01` | 仅快弹 |
| 300 分力量敌军（`$C0`） | `$01` | 仅快弹 |
| 其余敌军 | `$00` | 普通 |

**1-2 星只是子弹变快，破坏范围与普通弹完全相同。**

## 3. 坦克

### 3.0 移动速度＝靠「跳帧」实现，步长恒为 1 像素

`sub_DBF1_tank_movement` @ `$DBF1`。方向单位向量表 `tbl_E46C`/`tbl_E470` = `{$00, $FF, $00, $01}`，
即**每次移动恒为 1 像素**；速度差异全部由「这一帧要不要处理这辆坦克」决定：

| 对象 | 判定代码 | 处理频率 | 实际速度 |
|---|---|---|---|
| 玩家（index < 2） | `frm&1 != 0` 处理；否则 `frm&3 == 0` 才处理 | 每 4 帧动 3 次 | **0.75 px/帧** |
| 200 分快速敌军（type `$A0`） | 直接处理 | 每帧 | **1.0 px/帧** |
| 其余敌军 | `(index XOR frm) & 1 != 0` 才处理 | 每 2 帧动 1 次 | **0.5 px/帧** |

> 玩家跳过的是 `frm%4 == 2` 那一帧。敌军用 `index XOR frm` 而不是单纯 `frm&1`，
> 是为了让相邻编号的敌军错开在不同帧移动，摊平每帧的计算量。

冻结时钟（`ram_clock_timer`）在敌军分支里先判：非 0 时敌军直接跳过移动，但**正在爆炸/重生的敌军不受冻结影响**。

### 3.1 网格吸附（关键设计）

`$DBD5`「align player tank positions」：玩家**转向到垂直方向时**把坐标做 `pos = (pos+4) & 0xF8`，即**对齐到 8 像素网格**。

因此 `u` 恒为 8 的倍数，2.2 的四个探测点正好落在 4 个相邻的 4px 单元里，
**凿出的通道恰好等于开火坦克自身 16px 的投影——「开出的路必然够自己过」是刻意设计，不是巧合。**

> 敌方坦克没有显式的对齐指令，靠 AI「坐标 %8==0 时才换向」间接保证。

### 3.2 通行判定

`$DCD5-$DD02`：取坦克前方两角所在 tile，`tile == 0` 或 `tile >= 0x20`（空/冰/树）才可通行；
`tile >= 0x80`（坦克隐形墙/老鹰）或 `$01`-`$1F`（**任何残留砖 bit**、钢、水）都挡住。

> **一个 8×8 tile 必须 4 个子块全清空，坦克才能进入。**
> 俄文原文：«при уничтожении части кирпичного блока, танк не может въехать на освободившееся пространство — ведь сам тайл не был уничтожен»

## 4. CHR-ROM 图形资源索引

`CHR_ROM.chr` = 8192 字节 = **512 个 8×8 tile**。
格式：每 tile 16 字节，前 8 字节 bitplane0、后 8 字节 bitplane1，
像素值 = `bit(plane0) | bit(plane1)<<1`（4 个色值）。

### 字库位置（实测确认）

| 内容 | tile 索引 |
|---|---|
| 数字 `0`-`9` | **304-313** |
| 小写 `e` / `f` | 318 / 319 |
| `©` | 320 |
| 字母 `A`-`W` | **321-343**（连续） |
| 字母 `Y` | **345** |
| 右箭头 / 下划线等符号 | 347-351 附近 |
| `PAUSE` 大字 | 第 17 行（tile 272-287）区域 |
| `STAGE` 大字 | 第 18 行（tile 288-303）区域 |
| `namcot` 商标 | 第 22 行（tile 352-367）区域 |

> **`X` 和 `Z` 不存在**：这两个 tile 位置（344、346）被其他图形占用。
> 原因是原版全部文本（`HI-SCORE` / `STAGE` / `I-PLAYER` / `PTS` / `TOTAL` /
> `GAME OVER` / `PAUSE` / `NAMCOT` / `CONSTRUCTION`）都不含这两个字母，卡带空间被省下来了。
> **字库中也没有连字符**，`HI-SCORE` 的 `-` 需另找或自绘。

### 解码示例（Java）

```java
byte[] data = Files.readAllBytes(chrPath);
for (int row = 0; row < 8; row++) {
    int plane0 = data[tile * 16 + row] & 0xFF;
    int plane1 = data[tile * 16 + 8 + row] & 0xFF;
    for (int column = 0; column < 8; column++) {
        int bit = 7 - column;
        int value = ((plane0 >> bit) & 1) | (((plane1 >> bit) & 1) << 1);
        // value: 0=背景, 1..3=调色板索引
    }
}
```

## 5. 精灵表布局（pattern table 0）

已用 `CHR_ROM.chr` 逐像素校验：pattern table 0 的 256×256 区域按 16×16 坦克排成 8 行 8 列，
**四个象限是同一份索引图的四次调色板替换**（三次象限比对索引差 = 0）：

| 象限原点 | 调色板 |
|---|---|
| (0, 0) | palette 0 — 1P 黄 |
| (0, 128) | palette 1 — 2P 绿 |
| (128, 0) | palette 2 — 敌军银白 |
| (128, 128) | palette 3 — 红 |

**象限内行偏移（极易切错，务必核对）**：

| 行偏移 | 内容 |
|---|---|
| +0 / +16 / +32 / +48 | 玩家 0 / 1 / 2 / 3 星 |
| **+64 / +80 / +96 / +112** | **敌军 basic / fast / power / armor** |

**列偏移** = `方向 × 32 + 履带帧 × 16`，方向序 **U=0, L=1, D=2, R=3**。

### 精灵调色板

`sub_D53E_set_sprites_palette` @ `$D53E` 全程只写一次，不随关卡变。
`tbl_D555_sprites_palette` @ `$D555` = `0F,18,27,38 / 0F,0A,1B,3B / 0F,0C,10,20 / 0F,04,16,20`：

| # | 配色 | 三个前景色 |
|---|---|---|
| 0 | 1P 黄 | 暗橄榄 `#6B6B00` / 橙 `#E79C21` / 淡黄 `#E7E794` |
| 1 | 2P 绿 | 暗绿 `#005200` / 绿 `#008C31` / 淡绿 `#B5F7CE` |
| 2 | 敌军银白 | 暗青 `#00424A` / 灰 `#ADADAD` / 白 `#FFFFFF` |
| 3 | 红 | 暗紫 `#5A007B` / 红 `#B53121` / 白 `#FFFFFF` |

## 6. 敌军坦克的配色状态

`ram_tank_type`（`$00A8+X`）一个字节承载三件事：

- **bit7-5 种类**：`$00/$20/$40/$60` = 玩家 0-3 星，`$80/$A0/$C0/$E0` = 敌军 100/200/300/400 分
- **bit2**：道具携带者标志
- **bit1-0**：剩余装甲层数

### 装甲坦克（400 分）

**只换调色板，完全不换 tile**——绘制时 `tile = (type AND $F0) + wheels + dir*8`，低两位血量被掩掉，
所以四个血量状态的车型完全相同。

激活时 `ORA #$03` 得 `$E3`；每次中弹 `AND #$03` 非 0 则 `DEC`（`$E3→$E2→$E1→$E0`），为 0 才爆炸，共 4 发。

配色不是「每中一发换一个固定色」，而是**每帧在两色间交替**（NES 每帧换一次调色板、两帧一循环 = 30Hz，
CRT 上被眼睛积分成混合色）：`palette = tbl_E003[((frame<<2) + type) AND 7]`，
`tbl_E003` = `02,00,00,01,02,01,02,02`：

| 剩余装甲 | 交替配色 | 观感 |
|---|---|---|
| 4（满血） | 绿 ↔ 银白 | 青绿 `#004A25/#569C6F/#DAFBE6` |
| 3 | 黄 ↔ 银白 | 米黄 `#355625/#CAA467/#F3F3CA` |
| 2 | 黄 ↔ 绿 | 黄绿 `#355E00/#739429/#CEEFB1` |
| 1 | 恒定银白 | 与普通敌军无异 |

> **注意满血是绿色**，不是"受损才变色"。basic / fast / power 的低两位恒为 0 → `tbl[0]=tbl[4]=$02` → 全程银白，无任何变色。

### 道具携带者

走 `$DFBA` 独立分支且**优先级高于装甲配色**（原版先判 bit2）：
`palette = (frame>>3 AND 1) + 2`，即**银白 ↔ 红每 8 帧一换**（约 133 ms）。

装甲车恰好是携带者时（第 4/11/18 辆）类型被强制成 `$E4`：第一发命中先掉道具、
再因 `CMP #$E4` 多 `DEC` 一次 → `$E3`、然后常规 `DEC` → `$E2`，总血量仍 4 发，
但道具在第一发就掉、且永远不显示满血绿。

### 其他状态

- 冻结时钟：只拦移动，不改配色
- 玩家友军火 stun：整车隐现，每 8 帧切换
- 无敌头盔：独立叠加的精灵，**车身不变色**
- 出生星形：用 palette 3

## 7. 关卡结算画面

### 画面切换

全屏重绘，**不叠在战场上**：画进另一块 nametable（`$2800`），把 PPUCTRL 的 base nametable 切到 #2。
`sub_CEF7` 先关渲染 → 清缓冲 → 写属性表 → 整块拷贝 → 开渲染，
所以视觉上是**黑屏 1~2 帧后硬切**，没有淡入。

结束后 base nametable 复位，`sub_CC90_close_grey_curtain` @ `$CC90` 用灰 tile `$11`
**上下对开合拢 16 帧**（≈266 ms），再开幕进入下一关。

### 版式（32 列 × 30 行，每格 8×8；数字一律右对齐、抹前导零）

| 行 | 内容 |
|---|---|
| 3 | `HI-SCORE`（col 8-15）+ 最高分（右边界 col 23） |
| 5 | `STAGE`（col 12-16）+ 关号（右边界 col 19） |
| 7 | `Ⅰ-PLAYER`（col 3-10）、`Ⅱ-PLAYER`（col 21-28，仅双人） |
| 9 | 1P 总分（右边界 col 10）、2P 总分（右边界 col 28） |
| **12 / 15 / 18 / 21** | 四条统计行（100/200/300/400 分档），**间隔 3 行** |
| 22 | 横线：8 个 tile `$5C`（col 12-19）。**单人也照画整条**（原版小瑕疵） |
| 23 | `TOTAL`（col 6-10）+ 1P 总击杀（右边界 col 13）+ 2P（右边界 col 19） |
| 25 / 26 | `BONUS!` + `1000 PTS`（仅双人、非 game over、击杀多且还有命的一方） |

单条统计行的排列（左→右）：
`1P累计分 → PTS → 1P击杀数 → ←(tile $5B) → 坦克图标 → →(tile $5D) → 2P击杀数 → 2P累计分 → PTS`

> 坦克图标是**精灵**不是背景 tile（`sub_D0B8` 每帧重画），x=121..136，y=93/117/141/165。

### 动画时序（帧为单位，NTSC 1 帧 ≈ 16.64 ms）

**不是「逐行滑出」，而是「逐行计数」**：静态版式一次性全画出，真正的动画是四条统计行的
**数字从 0 开始逐个跳动累加**，一行数完再数下一行，从上往下。

| 阶段 | 帧数 |
|---|---|
| 最后一辆敌军被打掉 → 进结算 | 128 帧（≈2.13 s；有 GAME OVER 时 256 帧） |
| 画完版式后等待 | 30 帧（≈500 ms） |
| **每一次计数跳动** | **9 帧（≈150 ms）**，每跳播一记短「嘀」 |
| 档间停顿 | 20 帧（≈333 ms） |
| 四档数完 → 画 TOTAL | 30 帧 |
| TOTAL → BONUS 判定 | 15 帧 |
| 最后停留 | 120 帧（≈2.00 s） |

典型单人全清（8/5/4/3 分布）总时长 ≈ **475 帧 ≈ 7.9 s**；最短（0 杀）≈ 4.9 s。

音效：每次跳动同时触发 `ram_sfx_score_count_1`（`$0313`，方波）+ `_2`（`$0314`，噪声）。
**结算画面没有背景音乐**（进画面前已 `clear_sound_engine_data`）。

### 配色（背景调色板 `con_bg_pal_03` @ `$D595`）

字形 tile 只用 2bpp 的像素值 0 和 3，所以每个子调色板只有「颜色 3」决定文字颜色：

| 元素 | 颜色 |
|---|---|
| `HI-SCORE` 标签、`Ⅰ/Ⅱ-PLAYER`、`BONUS!` | `#F83800` 亮红橙 |
| 最高分数字、1P/2P 总分 | `#FCA044` 琥珀 |
| `STAGE`、统计行、横线、`TOTAL`、`1000 PTS` | `#FCFCFC` 白 |

## 8. 敌军 AI

### 8.1 状态机

`ram_tank_flags`（`$00A0+X`）高 4 位是状态、低 2 位是方向（0=上 1=左 2=下 3=右）。
`sub_E420` 改状态时**保留低 4 位**（方向不变）。

| 状态 | 含义 |
|---|---|
| `$00` | 空槽 |
| `$10`-`$70` | 爆炸与加分 |
| `$80` | 撞墙后停顿 |
| `$90` | 撞墙后重决策 |
| `$A0` | 正常移动 |
| `$B0` / `$C0` / `$D0` | 追基地 / 追 2P / 追 1P |
| `$E0` / `$F0` | 材质化后半段 / 前半段 |

**整个 AI 就是这个状态机，没有别的东西。**

### 8.2 换向：每前进 8px 掷一次 1/16，不是定时器

`ofs_000_DC7C_A0` @ `$DC7C`：仅当 `pos_X & 7 == 0` **且** `pos_Y & 7 == 0`（8px 网格对齐）时掷随机数，
`rnd & 0x0F == 0`（1/16）才调 `sub_DE72` 决策，**且该 tick 不移动**。

坦克每 tick 走 1px → 每 8 个 tick 才碰到一次网格点 → 等价于**每前进 8px 掷一次 1/16**。
期望自发换向间隔 = 128px 行程：普通敌军 ≈ 4.27 s、快速敌军 ≈ 2.13 s。

### 8.3 决策核心：三阶段激进度（最重要的 AI 行为）

`sub_DE72` @ `$DE72`。令 `S = ram_enemy_spawn_interval`（见 8.6），
`T = ram_frm_cnt_hi`（关卡开始清 0，**每 64 帧 +1**，约 1.0667 s 一格）：

1. `T > (S>>2)` → 状态 `$B0`，目标 = **基地** (120,216)
2. 否则 `T > (S>>3)` → 目标 = **玩家**（`$C0`/`$D0`）
3. 否则 → `rnd & 3` 得纯随机方向，状态 `$A0|dir`

**坊间「有一定概率朝基地移动」的说法是错的**：实际是按关内经过时间**硬切阶段**，
切换后所有敌军 100% 朝目标走。

| 关卡/模式 | S | 随机阶段 | 追玩家至 | 之后 |
|---|---|---|---|---|
| 关 1 单人 | 186 | ≈24.5 s | ≈49.1 s | 追基地 |
| 关 35 单人 | 50 | ≈6.4 s | ≈12.8 s | 追基地 |
| 关 1 双人 | 166 | ≈21.3 s | ≈43.7 s | 追基地 |
| 关 35 双人 | 30 | ≈3.2 s | ≈7.5 s | 追基地 |

> `ram_frm_cnt_hi` 是 8 位，第 256 格（≈273 s）后回绕到 0，AI 退回随机阶段（原版遗留行为）。

**追谁**（`$DE8E`）：1P 不存在 → 追 2P；否则敌军槽号为偶数 → 追 1P；否则 2P 不存在 → 追 1P；否则追 2P。

### 8.4 朝目标选方向：纯贪心、零寻路

`sub_DDA2` @ `$DDA2`。`sx = sign(target_x − tank_x)`、`sy = sign(target_y − tank_y)`，
`index = (sy+1)*3 + (sx+1)`，**再掷 1/2 随机**决定用竖直优先表还是水平优先表（`rnd & 1` 时 `index += 9`）。

`tbl_E486` @ `$E486` 共 18 项：
- 竖直优先（0-8）= `[上,上,上, 左,上,右, 下,下,下]` —— sy≠0 就沿 Y 走
- 水平优先（9-17）= `[左,上,右, 左,上,右, 左,下,右]` —— sx≠0 就沿 X 走

**完全不看墙**，撞上就走撞墙分支。追击是**一次性选向**：`$B0`/`$C0`/`$D0` 的 handler 算完方向就写回
`$A0|dir` 并 RTS（本 tick 不移动），下一 tick 回到普通移动，要到下次掷骰或撞墙才重新考虑。

### 8.5 撞墙

通行判定取移动后位置的**两个前角**，`tile == 0` 或 `tile >= $20`（空/冰/树）才可通行。被挡时掷 `rnd & 3`：

- **3/4**（≠0）→ 状态 `$88|dir`，每 tick `flags -= 4`，`flags & $0C == 0` 时回 `$A0`
  → **原地停 2 tick 后原方向再顶一次**，方向不变
- **1/4**（==0）→ 进 `$90`，并无条件 `flags ^= $02`（**掉头 180°**）

`$90` handler（`$DD48`）：1/2 概率走完整决策（`sub_DE72`），1/2 概率 `dir ±1`（因已掉头，落在两个垂直方向，各 1/4）。
净效果：撞墙后 **1/2 重新决策、1/4 左转、1/4 右转**。

**敌军永远不会主动停下**——没有 STOP 选项，唯一静止是撞墙停顿、材质化、冻结。

### 8.6 开火与出怪

**开火**（`sub_E162` @ `$E162`）：每帧对每辆敌军掷 `rnd & 0x1F == 0`（**1/32**）。
不看前方有无目标、不瞄准，方向就是当前朝向。平均 ≈533 ms 一次。
**每辆敌军同屏只能有 1 发子弹**（2 发是玩家 2 星以上专属）。四种敌军开火频率完全相同。
冻结期间**完全不开火**。

**出怪间隔**（`$C39E`）：`interval = 190 − 4 × 关号` 帧，双人再 `−20`。
关 1 单人 186 帧 ≈ 3.10 s，关 35 单人 50 帧 ≈ 0.833 s。
**开局 timer 为 0，第 1 帧就出第 1 辆**，之后每隔 interval 出 1 辆——开场只有 1 辆，
第 4 辆要到 3×interval（关 1 单人约 9.3 s）才到齐。
**冻结期间照常出怪**（`sub_DB48` 不查冻结计时器）。

**同屏上限**：`ram_enemy_limit` 单人 `$05`、双人 `$07`，扫描区间 `[2, limit]`
→ **单人 4 辆、双人 6 辆**。

**出生点轮转**（`sub_E363` @ `$E37C`）：index 每次**先 INC 再用**，等于 3 回绕 0
→ 顺序是 **中 → 右 → 左 → 中 → …**。位置 X = `$18`/`$78`/`$D8`，Y 恒 `$18`。
**没有「出生点被占用则换点/延迟」的逻辑**，材质化中的坦克不挡路也不被挡，允许重叠。

**材质化时长**：`$F0` 与 `$E0` 各 14 个处理 tick，共 28 tick；材质化中 type 不是 `$A0`
→ 按每 2 帧一次处理 → **56 帧 ≈ 0.93 s**。期间不移动、不开火、不被命中、不参与坦克互挡。
星形 tile = `$A1 + 4×|n−7|`，即「小→大→小」脉动两轮。

### 8.7 难度只有两条通道

1. `ram_enemy_spawn_interval` 同时决定**出怪间隔**和 **AI 三阶段切换时刻**，关号越大两者都越激进
2. 每关的**敌军类型构成**：`tbl_E4EC` @ `$E4EC` 给出该关 4 段的类型码，`tbl_E578` @ `$E578` 给出各段数量（合计 20）。
   敌军**按段成批出现**而非打散——例：关 1 = 先 18 辆普通再 2 辆快速；关 2 = 先 2 辆装甲、再 4 辆快速、再 14 辆普通

**换向概率、开火概率、移动速度都不随关卡变化。**

### 8.8 其他确认事实

- **冰面对敌军无影响**（`sub_E181` 的冰判定被 `CPX #$02 / BCS` 挡住，只给玩家）
- **敌军不吃道具**（拾取循环只覆盖玩家槽）
- **敌军子弹打不到敌军**（打坦克的循环只放行子弹槽 0/1/8/9 = 玩家的四发）
- **坦克互挡＝地形字节 bit7「隐形墙」**：每帧 `sub_E181` 给存活坦克脚下 tile 打 bit7 →
  `sub_DBF1` 移动（`>= $80` 不可进）→ `sub_E1FA` 立刻清掉。爆炸中与材质化中的坦克不打标记
- 敌军激活初始朝向**朝下**（`tbl_E47E`）
- **300 分力量型（`$C0`）低两位为 0 → 一发就炸**；只有 400 分装甲型（`$E0`，激活时 `ORA #$03`）需要 4 发
- 冻结时钟 `$0A`，每 64 帧 −1 → **640 帧 ≈ 10.67 s**

## 9. 道具系统

### 9.1 携带者与掉落

- **固定为本关第 4、11、18 辆出生**的敌军（`ram_enemy_spawn_cnt` 等于 `$11`/`$0A`/`$03` 时置 bit2）
- **新携带者一出生，场上未拾取的旧道具立刻被抹除**（`$E3A5`）
- **只有玩家子弹**命中携带者才掉道具，且**不管是否打死**（命中即 `sub_E8BE_spawn_bonus`）
- 装甲携带者（`$E4`）第一发命中先掉道具再额外 DEC 一次，总血量仍 4 发，永不掉第二次
- **手榴弹炸死携带者不掉道具**（`tank_type` 被直接清 0）

### 9.2 落点：只有 16 个固定点，且不避地形

`sub_E8BE_spawn_bonus`：X 与 Y 各取 `rnd & 3`，映射为 `{$30,$60,$90,$C0}` = {48,96,144,192}（屏幕像素，道具中心）。
相对战场 = {32,80,128,176}，**对齐 8px tile 网格、相对 block 网格偏移半格**。

**唯一的重摇条件是「玩家在 12px 内」**——完全不检查砖/钢/水/树/基地/敌军/出生点。
道具可以落在钢墙里、水里、基地墙上，玩家得自己打通去拿。

### 9.3 其他规则

- **同屏只有一个道具**（全局单组 `ram_bonus_pos_X/Y/id`），后来的直接覆盖前一个
- **道具永不超时消失**。只有三种消失途径：被拾取、新携带者出生、关卡结束
- **闪烁恒定 8 帧亮 / 8 帧灭**（周期 ≈266 ms），全程不变，没有临近消失的加速预警
- **类型加权 8 选 1**（`tbl_E8FA` @ `$E8FA`）：星 25%、手榴弹 25%、头盔/时钟/铲子/坦克各 12.5%
- **手枪（id 06）不在表里，永远抽不到**；即便强改内存，其 handler `ofs_bonus_EA48_06_RTS` 就是一条 RTS，**没有任何效果**
- 随机源 `sub_D44D` @ `$D44D`：`random = random*7 + frm_cnt_hi + ZP[++index]`
- **拾取判定**：中心距 `|dx| < 12 且 |dy| < 12`（比 AABB 相交更严格），**P2 优先**（索引从 1 递减）
- **拾取得分恒定 500**，随后调 `sub_D138`：**首次满 20000 分送一条命**（每名玩家一生只送一次）
- 拾取后原位置显示 16×16 的「500」精灵 50 帧 ≈ 832 ms

### 9.4 六种道具的精确效果

| 道具 | 效果 |
|---|---|
| **头盔** | `helmet_timer = $0A`，每 64 帧 −1 → **640 帧 ≈ 10.65 s**。重复拾取是覆盖不是叠加。护盾精灵 tile `$29`/`$2D` 每 2 帧交替，**车身不变色** |
| **时钟** | `clock_timer = $0A` → **≈10.65 s**。冻结期间：敌军不移动、完全不开火；但**新敌军照常出生**；冻结中的敌军**可正常击杀并计分**；不改变配色 |
| **铲子** | 把基地墙整体重画成钢（顺带修复已破损部分），`shovel_timer = $14` → **1280 帧 ≈ 21.30 s**。到期变回**砖**（不是消失）。`timer < 4`（最后 ≈3.195 s）进入预警：每 16 帧（≈266 ms）在钢/砖之间来回重画，约 6 个来回。**这是真改地形**——闪成砖的那 16 帧里普通子弹真能打掉它 |
| **五角星** | 上限 3 星，每次 +1。1-2 星只是**子弹变快**（破坏范围与普通弹相同），3 星才是快弹+强弹（整 tile 清零、可破钢）。玩家死亡时星级清 0，过关不清 |
| **坦克** | `INC ram_lives`，**代码里没有上限** |
| **手榴弹** | 清除**当前场上存活的敌军**（同屏上限内），不影响后备队列。**不计分、不计入结算统计**（`tank_type` 被清 0），但过关的 20 辆计数照常扣——所以用手榴弹清屏会让结算画面的击杀合计小于 20 |

> 基地墙写入区域实际是 6×4 个 tile 的矩形，**外圈会被写成 `$00` 清空**——
> 即每次画/重画基地墙都会抹掉基地墙外侧一圈的地形。

**速度换算**（原版 60 fps、步长 1px；本项目 2ms 逻辑步 = 500 步/秒、缩放 2.5×）：
`本项目 px/步 = 原版 px/帧 × 60 × 2.5 ÷ 500 = 原版 px/帧 × 0.3`

| 对象 | 原版 | 本项目应为 |
|---|---|---|
| 玩家坦克 | 0.75 px/帧 | **0.225** px/步 |
| 普通/力量/装甲敌军 | 0.5 px/帧 | **0.15** px/步 |
| 快速敌军（200 分） | 1.0 px/帧 | **0.30** px/步 |
| 普通子弹 | 1.0 px/帧等效 | **0.30** px/步 |
| 快弹（1 星以上/快速敌军） | 4.0 px/帧 | **1.20** px/步 |
